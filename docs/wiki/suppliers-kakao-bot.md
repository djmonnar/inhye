# 거래처별 가격 · 카카오 챗봇

## 1. 거래처별 가격 (스키마 v6, 2026-11-13)

같은 소품도 거래처마다 값이 다르고, 같은 거래처도 때마다 값이 바뀌어요. 그래서 상품 하나에 원가 한 칸으로는 부족해서:

| 표 | 한 줄의 뜻 | 쓰는 곳 |
| --- | --- | --- |
| `product_sources` | **상품 × 거래처** 하나 — 그 거래처의 최근 개당 가격·확인한 날·구매 링크·거래처 상품명·메모 | 상품 화면 ‘거래처별 가격’, 거래처 화면, 챗봇 |
| `price_logs` | 가격을 확인할 때마다 한 줄 (직접 / 입고 / 카톡) | 상품 화면 ‘가격 기록’ ▲▼ |

- `products.supplier_id` = **주 거래처**(평소에 사는 곳), `products.cost_price` = 마진 계산용 **지금 원가** — 그대로 둬요.
- 가격은 `record_price()`로만 기록해요(거래처별 가격 갱신 + 기록 한 줄 + 선택하면 원가도). 앱(직원 이상)과 챗봇 서버(서비스 키) 둘 다 써요.
- **입고할 때 ‘산 곳’과 ‘개당 매입가’를 적으면 자동으로 가격 기록**돼요(`stock_moves_price` 트리거).
- 상품의 주 거래처는 항상 거래처별 가격에도 한 줄 있어요(`products_source` 트리거 — 구매 링크·상품명도 채움).
- v6로 처음 올릴 때 한 번: 지난 입고 기록 → 가격 기록, 상품의 주 거래처·원가 → 거래처별 가격 (표가 비어 있을 때만 채워서, 나중에 다시 실행해도 지운 줄이 안 살아나요).
- 화면: 상품 → **🏷️ 거래처별 가격**(가격 순, 최저가 표시, ‘주 거래처로’, 오래된 가격(60일) 표시, 더 싼 곳 있으면 💡 아끼는 금액), 거래처 → ‘여기서 산 상품’에 이 거래처 가격과 더 싼 곳.
- 정렬·최저가 계산은 `src/lib/sources.ts` (앱·챗봇 공용).

## 2. 카카오 챗봇 (카카오 i 오픈빌더 스킬)

카카오톡 ‘포포하우스 관리’ 채널에서 거래처·발주·재고·매출을 보고, 거래처 등록·수정과 가격 기록을 해요.

### 구조
- 스킬 서버: `POST /api/kakao/skill` → `src/lib/server/kakao-bot/bot.ts`(말 해석·대화 흐름) + `supabase-db.ts`(데이터).
- 오픈빌더에서는 **폴백 블록 + 웰컴 블록**만 스킬에 연결해요. 모든 말을 서버가 해석해서 블록을 따로 만들 필요가 없어요.
- 응답 형식·길이 제한은 `kakao.ts` 한 곳에서 지켜요(simpleText 1000자, textCard 설명 400자, listCard 5개, 바로가기 10개·14자).
- 카카오는 **5초** 안에 답을 못 받으면 오류 → 서버가 4.3초에 ‘다시 보내 주세요’로 먼저 답해요. 오늘 매출은 빅솔론을 2.5초까지만 기다리고, 늦으면 저장된 매출(`pos_sales`)로 보여줘요.
- 여러 번 주고받는 대화(거래처 등록, 가격 기록 …)는 `kakao_bot_sessions`에 15분 동안 저장. ‘취소’로 언제든 그만.

### 보안 · 권한
- 스킬 요청 확인: 오픈빌더 스킬의 **헤더값** `X-Popo-Key` = Vercel `KAKAO_SKILL_SECRET`(비밀). 다르면 401. 값이 없으면 챗봇은 ‘서버 설정 필요’만 답해요.
- 채널은 누구나 친구 추가할 수 있어서, **앱 계정과 연결한 카톡만** 데이터를 봐요. 앱 → 더보기 → 카카오 챗봇 → ‘연결 코드 받기’(6자리, 10분, 한 번만) → 채널에 `연결 123456`.
- 권한은 연결한 앱 계정 그대로: 직원 = 보기·등록·수정·가격 기록, **거래처 삭제는 관리자만**. 승인 대기 계정은 아무것도 못 봐요.
- 표 `kakao_bot_users`(봇 사용자 키 ↔ 계정), `kakao_bot_codes`, `kakao_bot_sessions`는 서비스 키만 읽고 써요(정책 없음).

### 할 수 있는 말
| 말 | 하는 일 |
| --- | --- |
| 메뉴 / 도움말 / 취소 | 바로가기, 사용법, 하던 것 그만 |
| 거래처 목록 (2) | 자주 쓰는 곳부터 5곳씩 |
| 거래처 도매꾹 | 연락처·주문 조건·상품 수 + 사이트·전화·상품 보기 버튼 |
| 거래처 등록 (이름) | 이름 → 종류 → 사이트 → 담당자 → 전화 → 주문 조건 → 메모 (‘건너뛰기’, ‘여기까지 저장’) |
| 거래처 수정 도매꾹 | 고칠 칸 고르기 → 새 값 (‘지우기’로 비우기, ‘자주 쓰는 곳’은 바로 켜고 끄기) |
| 거래처 삭제 도매꾹 | 관리자만, 확인 후 삭제 |
| 거래처 상품 도매꾹 | 거기서 사는 상품(주 거래처 + 거래처별 가격에 있는 것), 그 거래처 가격, 더 싼 곳 |
| 상품 곰돌이 / 바코드 숫자 | 재고·판매가·원가·마진, 거래처별 가격(🏆 최저가), 다시 주문하기 버튼 |
| 가격 기록 (상품) | 상품 → 거래처 → 개당 가격(1800, 1,800원, 2만, 1만5천) → ‘기록하기’ 또는 ‘원가도 바꾸기’ |
| 발주 목록 | 품절·품절 임박을 주 거래처별 카드로: 추천 수량(발주 화면과 같은 계산), 예상 금액, 더 싼 곳 |
| 오늘 매출 | 빅솔론 오늘 판매 합계·많이 팔린 상품 |

### 처음 설정 (관리자, 한 번만)
1. Vercel 환경변수 `KAKAO_SKILL_SECRET`에 아무 긴 비밀 문자열 → 다시 배포. (예: PowerShell에서 `[guid]::NewGuid().ToString('N') | Set-Clipboard` 하면 클립보드에 복사돼요. 채팅·코드에 붙여넣지 않기)
2. 앱 `/setup`에서 DB 업데이트(스키마 v6).
3. 챗봇 관리자센터(chatbot.kakao.com) → 봇 ‘포포하우스관리’ → **스킬 → 생성**: 이름 `포포 스킬`, URL·Test URL `https://inhye.vercel.app/api/kakao/skill`, 헤더값 `X-Popo-Key` = 1번 값(Test 헤더도 같게), ‘기본 스킬로 설정’ 체크 → 저장.
4. **시나리오 → 기본 시나리오 → 폴백 블록**: 파라미터 설정의 스킬 선택에서 `포포 스킬` → 봇 응답 ‘스킬데이터 사용’ → 저장. **웰컴 블록**도 똑같이.
5. **배포** → 배포하기. **설정 → 카카오톡 채널 연결**에서 포포하우스 채널 연결.
6. 봇테스트에서 ‘메뉴’ → 연결 안내가 나오면 성공 → 앱에서 받은 코드로 `연결 123456`.

### 시험
- 대화 로직은 메모리 DB로 43개 대화(연결·목록·등록·수정·삭제 권한·가격 기록·발주·매출·조사)와 카카오 길이 제한을 확인했어요(2026-11-13). 실제 카카오·DB 연결은 위 설정 후 봇테스트로 확인.
