# 거래처별 가격 · 카카오 챗봇

## 1. 거래처별 가격 (스키마 v6, 2026-11-13)

같은 소품도 거래처마다 값이 다르고, 같은 거래처도 때마다 값이 바뀌어요. 그래서 상품 하나에 원가 한 칸으로는 부족해서:

| 표 | 한 줄의 뜻 | 쓰는 곳 |
| --- | --- | --- |
| `product_sources` | **상품 × 거래처** 하나 — 그 거래처의 최근 개당 가격·확인한 날·구매 링크·거래처 상품명·메모 | 상품 화면 ‘거래처별 가격’, 거래처 화면, 챗봇 |
| `price_logs` | 가격을 확인할 때마다 한 줄 (직접 / 입고 / 카톡) | 상품 화면 ‘가격 기록’ ▲▼ |

- `products.supplier_id` = **주 거래처**(평소에 사는 곳), `products.cost_price` = 마진 계산용 **지금 원가** — 그대로 둬요.
- 가격은 `record_price()`로만 기록해요(거래처별 가격 갱신 + 기록 한 줄 + 선택하면 원가도). 앱(직원 이상)과 챗봇 서버(서비스 키) 둘 다 써요.
- **입고할 때 ‘산 곳’과 ‘개당 매입가’를 적으면 자동으로 가격 기록**돼요(`stock_moves_price` 트리거).
- 상품의 주 거래처는 항상 거래처별 가격에도 한 줄 있어요(`products_source` 트리거 — 구매 링크·상품명도 채움).
- v6로 처음 올릴 때 한 번: 지난 입고 기록 → 가격 기록, 상품의 주 거래처·원가 → 거래처별 가격 (표가 비어 있을 때만 채워서, 나중에 다시 실행해도 지운 줄이 안 살아나요).
- 화면: 상품 → **🏷️ 거래처별 가격**(가격 순, 최저가 표시, ‘주 거래처로’, 오래된 가격(60일) 표시, 더 싼 곳 있으면 💡 아끼는 금액), 거래처 → ‘여기서 산 상품’에 이 거래처 가격과 더 싼 곳.
- 정렬·최저가 계산은 `src/lib/sources.ts` (앱·챗봇 공용).

## 2. 카카오 챗봇 (카카오 i 오픈빌더 스킬)

카카오톡 ‘포포하우스 관리’ 채널에서 거래처·발주·재고·매출을 보고, 거래처 등록·수정과 가격 기록을 해요.

### 구조
- 스킬 서버: `POST /api/kakao/skill` → `src/lib/server/kakao-bot/bot.ts`(말 해석·대화 흐름) + `supabase-db.ts`(데이터).
- 오픈빌더에서는 **폴백 블록 + 웰컴 블록**만 스킬에 연결해요. 모든 말을 서버가 해석해서 블록을 따로 만들 필요가 없어요.
- 응답 형식·길이 제한은 `kakao.ts` 한 곳에서 지켜요(simpleText 1000자, textCard 설명 400자, listCard 5개, 바로가기 10개·14자).
- 카카오는 **5초** 안에 답을 못 받으면 오류 → 서버가 4.3초에 ‘다시 보내 주세요’로 먼저 답해요. 오늘 매출은 빅솔론을 2.5초까지만 기다리고, 늦으면 저장된 매출(`pos_sales`)로 보여줘요.
- 여러 번 주고받는 대화(거래처 등록, 가격 기록 …)는 `kakao_bot_sessions`에 15분 동안 저장. ‘취소’로 언제든 그만.

### 보안 · 권한
- 스킬 요청 확인: 오픈빌더 스킬의 **헤더값** `X-Popo-Key` = Vercel `KAKAO_SKILL_SECRET`(비밀). 다르면 401. 값이 없으면 챗봇은 ‘서버 설정 필요’만 답해요.
- 채널은 누구나 친구 추가할 수 있어서, **앱 계정과 연결한 카톡만** 데이터를 봐요. 앱 → 더보기 → 카카오 챗봇 → ‘연결 코드 받기’(6자리, 10분, 한 번만) → 채널에 `연결 123456`.
- 권한은 연결한 앱 계정 그대로: 직원 = 보기·등록·수정·가격 기록, **거래처 삭제는 관리자만**. 승인 대기 계정은 아무것도 못 봐요.
- 표 `kakao_bot_users`(봇 사용자 키 ↔ 계정), `kakao_bot_codes`, `kakao_bot_sessions`는 서비스 키만 읽고 써요(정책 없음).

### AI로 알아듣기 + 주문 (2026-11-13)
- **정해진 말은 지금처럼 바로**(AI 안 씀). 그 밖의 말은: 이름 하나로 바로 찾아지면 찾기 결과, 아니면 **AI 해석기**(`kakao-bot/ai.ts` `route`)가 뜻을 골라서(주문·주문 목록·거래처·거래처 상품·등록·수정·상품·가격 기록·발주·매출·도움말) 챗봇의 정해진 명령으로 실행. 2.6초 안에 못 고르면(또는 ‘모름’) **낱말 안전망**(`keywordRoute`: 말 속 거래처 이름 → 거래처 카드, 발주·품절 → 발주 목록, 매출 → 오늘 매출, 주문 목록·거래처 목록·도움) → 그래도 없으면 이름 찾기. 문장인데 아무것도 못 찾으면 ‘찾은 게 없어요’ 대신 ‘잘 모르겠어요 + 이렇게 말해 보세요’. 거래처 삭제는 AI로 안 해요(정해진 말로만).
- **사용법 질문(AI 없이 바로, 2026-11-14)**: “발주 어떻게 넣어?”처럼 `어떻게·방법·하는 법·알려줘·하려면`이 있고 주제(발주·라벨·가격·주문·거래처·매출·상품)가 보이면 `kakao-bot/howto.ts`의 짧은 안내 + 바로 해 볼 버튼 + 앱 화면 링크. 정해진 명령보다 먼저 봐서 “거래처 등록 어떻게 해?”가 ‘어떻게 해?’라는 거래처를 만들지 않아요. 말에 거래처·상품 이름이 있으면(“곰돌이 재고 어떻게 돼?”) 그걸 묻는 거라 건너뛰고, “어떻게 됐어?”는 상태 질문이라 건너뛰어요. AI 해석기도 `howto` 뜻으로 여기에 와요.
- **콜백을 켜면 AI 해석도 기다려요**: 마감 안에 못 고르면 ‘무슨 말인지 알아보고 있어요 ⏳’로 먼저 답하고, 9초까지 기다려 고른 명령의 결과를 콜백으로 보내요(주문이면 주문 비서를 끝까지 기다려서 한 번에).
- 로그: `[kakao ai] route: <뜻> in <ms>` / `no answer in <ms>` / `route error after <ms>` — 말 내용은 안 남겨요. AI가 자주 늦으면 `OPENAI_FAST_MODEL`을 빠른 모델로.
- `OPENAI_FAST_MODEL`(선택)을 주면 해석기만 그 모델로(빠르고 싸게). 없으면 `OPENAI_MODEL`. `OPENAI_API_KEY`가 없으면 AI 없이 예전처럼 동작.
- **주문**: `주문 목록`(날짜·시간순, 7일 안 택배 알림), `오늘 픽업`/`내일 픽업`, 날짜·픽업·택배·꽃다발·보냈어·완료 같은 말이 있으면 바로 **주문 비서**(앱과 같은 `orderChat`, 등록·수정·완료·취소). 연결된 앱 계정이 만든 사람으로 남아요.
- **바로 처리(AI 없음, 2026-11-13)**: 주문 비서(`orders.ts` `orderChat`)가 먼저 `src/lib/orderParse.ts`로 읽어 봐요. 줄마다 `날짜(11/20·11월 20일·오늘/내일/모레) [요일] [시간] [픽업/택배] 이름 상품 [가격] [(메모)]`이면 바로 등록, 한 줄 `이름 … 보냈어/완료/찾아갔어/취소`면 그 이름의 진행 중 주문이 딱 하나일 때 바로 완료·취소. 한 줄이라도 애매하면(날짜 없음, ‘다음 주 화요일’, 상품에 숫자만 남음, 같은 이름 여럿) 메시지 전체를 AI로. 요일이 날짜와 다르면 날짜 기준으로 넣고 알려줘요. 앱 주문 비서도 같은 길이라 빨라졌어요.
- **5초 규칙**: 스킬 라우트가 `deadline`(요청 + 3.8초)을 줘요. 주문 정리가 그 안에 안 끝나면 세션에 `ai_job`(running)을 저장하고 ‘정리하고 있어요 ⏳ / 결과 보기’로 답한 뒤, Next.js `after()`로 끝까지 마무리해서 결과를 세션에 저장(done/error). ‘결과 보기’나 **같은 말을 다시 보내면 저장된 결과**를 보여줘서 두 번 등록되지 않아요. 90초 넘게 running이면 멈춘 걸로 안내. 다른 말을 보내면 기다리던 결과는 놔두고 새 말을 처리(그새 다른 대화를 시작했으면 결과가 덮어쓰지 않아요).
- **콜백(B)**: 블록에서 콜백을 켜면 요청에 `userRequest.callbackUrl`이 와요. 먼저 마감(3.8초)까지 기다려 보고, 그 안에 끝나면 **바로 보통 답**(콜백 안 씀). 늦을 때만 첫 답을 `{"version":"2.0","useCallback":true,"data":{"text":"주문을 정리하고 있어요 ⏳ 잠시만요!"}}`(template 없이)로 하고, 다 되면 `after()`에서 그 주소로 보통 스킬 답(JSON)을 POST(5분 안 한 번). 주소는 https면 받아요(요청 자체를 `X-Popo-Key`로 확인하니까) — 처음 쓸 때 로그에 `[kakao skill] callback host:`로 주소의 호스트를 남겨요. 콜백이 없으면 위 ‘결과 보기’ 방식.
- 시험: 메모리 DB + 가짜 AI로 46개 대화(사용법 질문·낱말 안전망·늦은 AI 해석 콜백 포함, 콜백 켜도 빠르면 바로 답 포함, 주문 목록·픽업·등록 결과·늦을 때 결과 보기·같은 말 다시 보내기·콜백·AI 해석 4종·이름 바로 찾기·AI 없음/느림/오류·다른 말·멈춘 작업·도움말·발주 목록과 안 헷갈림).

### 콜백 켜기 (B, 선택 — 켜면 ‘결과 보기’ 없이 답이 따로 와요)
카카오 화면은 자주 바뀌어서 메뉴 이름이 조금 다를 수 있어요.
1. **전환 신청은 찾지 않아도 돼요.** 예전엔 설정 → ‘AI 챗봇 관리’에서 ‘AI 챗봇 전환’(또는 메일)을 신청·승인받아야 했는데, 지금 설정 화면은 보통 ‘챗봇 관리 / 비즈월렛 정보 / 지식베이스 정보’ 탭뿐이에요(2026-11-14 사용자 화면도 메뉴 없음). 블록에 **Callback 설정**이 보이면 그걸 켜면 돼요.
2. **시나리오 → 폴백 블록** → 블록 상세의 **Callback 설정**(더보기 메뉴) 켜기 + 응답대기 메시지 → 블록 **저장**. 폴백 블록에서 안 켜지면: 새 블록 ‘주문 비서’를 만들고 예시 문장(“11/20 픽업 김포포 꽃다발”, “김포포 보냈어” 등)을 넣고 `포포 스킬` + 콜백을 켜요.
3. 오른쪽 위 **배포**. **봇테스트는 콜백을 완전히 지원하지 않아서** 실제 카톡 채널에서 시험해요. 앱 쪽 설정은 필요 없어요(콜백 주소가 오면 자동으로 써요). 확인: 서버 로그에 `[kakao skill] callback host:`가 찍히면 콜백 주소가 온 거예요(없으면 아직 꺼져 있음, `callback url ignored`면 주소가 이상함). 켰는데도 안 오면 챗봇 관리자센터 고객센터에 문의.

1. Vercel 환경변수 `KAKAO_SKILL_SECRET`에 아무 긴 비밀 문자열 → 다시 배포. (예: PowerShell에서 `[guid]::NewGuid().ToString('N') | Set-Clipboard` 하면 클립보드에 복사돼요. 채팅·코드에 붙여넣지 않기)
2. 앱 `/setup`에서 DB 업데이트(스키마 v6).
3. 챗봇 관리자센터(chatbot.kakao.com) → 봇 ‘포포하우스관리’ → **스킬 → 생성**: 이름 `포포 스킬`, URL·Test URL `https://inhye.vercel.app/api/kakao/skill`, 헤더값 `X-Popo-Key` = 1번 값(Test 헤더도 같게), ‘기본 스킬로 설정’ 체크 → 저장.
4. **시나리오 → 기본 시나리오 → 폴백 블록**: 파라미터 설정의 스킬 선택에서 `포포 스킬` → 봇 응답 ‘스킬데이터 사용’ → 저장. **웰컴 블록**도 똑같이.
5. **배포** → 배포하기. **설정 → 카카오톡 채널 연결**에서 포포하우스 채널 연결.
6. 봇테스트에서 ‘메뉴’ → 연결 안내가 나오면 성공 → 앱에서 받은 코드로 `연결 123456`.

### 시험
- 대화 로직은 메모리 DB로 43개 대화(연결·목록·등록·수정·삭제 권한·가격 기록·발주·매출·조사)와 카카오 길이 제한을 확인했어요(2026-11-13). 실제 카카오·DB 연결은 위 설정 후 봇테스트로 확인.
